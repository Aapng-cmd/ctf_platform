# Платформа CTF

Платформа в духе CTFd на Go и Gin: мастер настройки, пользователи и команды, задания Jeopardy, таблица, страницы, уведомления и режим «Атака-защита».

Интерфейс переключается между русским и английским в шапке. Выбор хранится в браузере (`localStorage`, ключ `ctf_lang`). По умолчанию язык русский.

Английская версия этого руководства: [README_en.md](README_en.md).

## Запуск

```bash
cp .env.example .env
# задайте SECRET_KEY, POSTGRES_PASSWORD и REDIS_PASSWORD в .env
docker compose up --build
```

Сайт открывается по HTTPS на локальном имени из `CERT_DOMAIN` (по умолчанию `ctf.local`). В `/etc/hosts` каждой машины добавьте строку с IP сервера:

```text
10.0.0.5  ctf.local
```

Откройте [https://ctf.local](https://ctf.local) и пройдите `/setup`. Запрос на 80 порт и на любой другой Host перенаправляется на это имя. Сертификат самоподписанный; файл `ca.crt` лежит в томе `certs` (`docker compose cp nginx:/etc/nginx/certs/ca.crt ca.crt`). Postgres и Redis наружу не публикуются.

Локальный запуск без Docker по-прежнему слушает `http://127.0.0.1:8000`.

Учётные записи, задания, раунды, проверки и кражи флагов лежат в Postgres 16. Флаги режима «Атака-защита» лежат в Redis 7. Флаги Jeopardy остаются в Postgres.

## Время

Часовой пояс один на всё событие. Он выбирается при настройке и в **Админка → Настройки** из списка городов. Подпись зависит от языка интерфейса: «Москва UTC+3» или «Moscow UTC+3». Смещение считается по текущим правилам летнего времени.

Все показанные даты и время — в этом поясе и в виде **ДД.ММ.ГГГГ ЧЧ:ММ**.

## Страница без перезагрузки

Сохранение форм, включая загрузку файлов, уходит через `fetch`. Браузер не перезагружает вкладку: обновляются шапка, содержимое страницы, сообщения и токен формы. Ссылки по-прежнему открывают страницу обычным переходом.

## Атака-защита

Jeopardy доступен всегда. Attack-Defense запускается и останавливается в **Админка → Attack-Defense**. Одновременно идёт только одно такое событие. Пауза его не архивирует. Остановка сохраняет дэшборд по раундам, без адресов команд, и останавливает и удаляет чекеры. Чекеры в архив не попадают. В архиве дэшборд можно листать по раундам или проиграть на 1x, 2x и 4x; там же видна каждая смена коэффициентов раунда.

Цепочка выкладки:

1. Загрузить архив чекера. Платформа запускает только чекер. Уязвимый сервис из архива не стартует: его поднимают команды у себя.
2. Создать сервис: имя, порт и чекер из списка уже запущенных. Путь к чекеру вручную не пишется.
3. Указать хост каждой команды.
4. Сервис сам ставится на хост каждой команды. Порт берётся у сервиса, поэтому у всех команд он одинаковый, а хосты разные.

Один чекер обслуживает один сервис у всех команд. Генератор флагов выдаёт каждой команде свой флаг.

Имя сервиса, порт и чекер можно изменить после создания. Очки за атаку, защиту, потерю флага, SLA и простой задаются в общих настройках атаки-защиты, а не у отдельного сервиса.

Капитан команды может записать хост на странице `/attack`. Порт там не меняется.

Пустой хост считается простоем каждый раунд: команда не получает SLA и платит штраф простоя.

### Очки

Значения по умолчанию:

| Событие | Очки |
| --- | --- |
| Атака: украден флаг другой команды | +10 атакующему |
| Потеря флага: украден свой флаг | −10 жертве |
| Защита: свой флаг прожил весь срок на работающем сервисе и не был украден | +5 |
| SLA: раунд со статусом OK | +2 |
| Простой: DOWN, MUMBLE, CORRUPT или нет хоста | −20 × число соперников |

Упавший сервис обходится дороже, чем если флаг украдут все соперники. Статус ERROR означает, что платформа не достучалась до своего чекера, и команде за него очки не меняются.

Пока событие идёт, администратор может несколько раз начислить или снять очки команде. В скобках — итоговая сумма этих изменений, а не последнее. На SLA эта сумма не умножается. Число перед скобками — итоговый счёт. Если администратор ничего не менял, скобок нет.

### Подготовка

**Подготовка (минуты)** держит чекеры выключенными, а счёт неподвижным, пока окно не кончится. Окно начинается в момент сохранения настроек. Нулевая длительность отключает его. Чтобы после подготовки пошли раунды, снимите паузу движка.

### Чекер

Чекер отвечает на HTTP `POST` с JSON:

```json
{"action":"put","team_id":1,"host":"10.0.1.10","port":8080,"flag":"FLAG{...}","round":3,"service":"web"}
```

`action` — `put`, `get` или `check`. Ответ: `{"status":"OK|DOWN|CORRUPT|MUMBLE","message":"..."}`.

Каждый раунд платформа кладёт новый флаг и забирает его обратно. `jury/spawn.py` платформа не запускает.

### Сдача флага

Страница `/attack` или запрос с токеном команды. CSRF не нужен только у `POST` и `PUT /api/v1/ad/flags`, и только если запрос несёт `X-Team-Token`. Форма на сайте этот заголовок не ставит и передаёт токен сессии.

```bash
curl -s -X POST https://ctf.local/api/v1/ad/flags \
  -H 'X-Team-Token: TEAM_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '["FLAG{...}"]'
```

Свой флаг возвращает `own_flag` и текст `Cannot submit own flag`. Во время подготовки сдача отвечает 403.

Таблица `/dashboard` открыта гостям, пока видимость счёта не скрыта и не ограничена администраторами. Открытый дэшборд опрашивает сервер каждые 3 секунды. Запись в архиве не опрашивает: раунды листаются или играются на 1x, 2x и 4x. Единица скорости — длительность самого этого раунда.

## Несколько копий сайта

Часы Attack-Defense и Docker ведёт один процесс (`AD_ENGINE=true`, это значение по умолчанию). Остальные копии ставят `AD_ENGINE=false` и не получают сокет Docker. Общий у копий `SECRET_KEY`. `DB_MAX_OPEN` — пул базы одного процесса, он удерживается между 4 и 128. Запрос пишется одной JSON-строкой в stdout, без тела, query и cookie. Успешный опрос дэшборда в лог не попадает.

## Тестовый стенд

`scripts/ad_bootstrap.py` создаёт администратора и команды alpha, bravo, gamma. Если заданы каталог задачи и zip чекера, скрипт поднимает сервис на `10.255.66.1`, `10.255.66.2` и `10.255.66.3` на одном порту, загружает чекер, создаёт сервис и записывает хосты. Адреса 127.0.0.0/8 платформа больше не принимает. Сайт по умолчанию — `https://ctf.local`.

```bash
python3 scripts/ad_bootstrap.py
```

По умолчанию задача `/home/kali/my_AD_examples/AD1/bucket`, архив `bucket.zip`, порт `18101`. Переменные: `BASE`, `PREP_MINUTES`, `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `TASK_DIR`, `CHECKER_ZIP`, `BASE_PORT`, `CHECKER_HOST`, `CTF_TIMEZONE`.

Учётные данные скрипт печатает в конце. Пароль уже существующего администратора скрипт не подбирает.
